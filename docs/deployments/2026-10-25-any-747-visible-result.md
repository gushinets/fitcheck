# ANY-747 — observe results only in a visible document

Date: 2026-10-25 (Europe/Moscow). Local implementation for
[ANY-747](https://linear.app/paveldik/issue/ANY-747); not deployed or committed by this task.

## Behavior

Both `DemoAnalysis` and `WebsiteApp` previously marked results viewed immediately
on completion, including in a background tab. They now require an actually rendered
result and `document.visibilityState === 'visible'` before marking the result viewed
or emitting `analysis_result_viewed`. Hidden completion waits for `visibilitychange`.
Leaving the result screen or unmounting removes the listener. Account observations
also retain the identity generation guard and require the authenticated result UI.

The existing result ID / operation context and per-mount deduplication are unchanged.
Reopening a result after remount may still produce another observation; the report's
first-view/activation deduplication and server ownership proof remain authoritative.
Job completion does not become a product view. The event timestamp is generated by
the real metrics client at the visible observation, so a background job cannot end
TTV before the visitor returns. Browser clock skew remains separate work (ANY-748).
This observes a visible UI, not human reading or viewport intersection.

## Verification

- Before the fix, all six new component cases failed because a hidden result emitted
  `analysis_result_viewed`. After the fix, the two affected files passed all 30 tests.
- Full frontend suite: **552 passed, 3 skipped** (53 passed files, 2 skipped files).
- TypeScript, production build and ESLint for the changed TypeScript files passed.
  The pnpm launcher could not fetch/verify its pinned release in this environment;
  verification used the already installed local Node CLIs directly.
- Component controls cover pending demo/account completion while hidden, first visible
  observation, repeated visibility changes, navigation away, unmount, and demo resume.
- Real headed Chromium smoke: **2 passed**, demo and account. A deterministic local
  backend, real auth/storage/queue and captured free analysis fixtures were used.
  The browser transport captures real metrics client batches and acknowledges them
  with `{ delivered: true }`; it does not send data to an external collector.
- Smoke observed actual `hidden` state while result DOM completed, no view before
  returning, exactly one view with `occurredAt >= returnedAt`, and no duplicate on
  another real tab switch. Each run attaches synthetic observation JSON to its
  Playwright result. No paid LLM requests, dev data or user browser profiles were used.
- Independent review found no remaining substantive issues.

Reproduce locally with the existing loopback PostgreSQL test service available:

```sh
node node_modules/next/dist/bin/next build --webpack
node node_modules/@playwright/test/cli.js test --config playwright.visibility.config.ts --headed
```

The smoke uses only the guarded `fitcheck_e2e_test` database through `e2e/backend.py`.
That fixture truncates this dedicated database. It never reads `backend/.env`.

Playwright normally forces focus/visibility through its own CDP session, even after
switching tabs. A second CDP session cannot clear that session's override. The smoke
therefore launches a disposable Chromium profile and attaches with the public
`connectOverCDP({ noDefaults: true })` API to its default persistent context. No
`document.visibilityState` property or visibility event is spoofed. The temporary
browser is closed and its profile removed in `finally`. The regular E2E configuration
skips these two tests; use the dedicated headed configuration above.

## Rollout

Frontend-only deployment: rebuild and deploy the website normally. No database
migration, backend configuration, API restart or worker change is required.
On the deployed website, repeat the demo/account background-completion checks using
an approved test fixture; this task verified the local environment, not deployed dev.
Rollback is a frontend redeploy of the previous commit; already stored false views
are not rewritten by this change.
